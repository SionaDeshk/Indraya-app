# INDRAYA
Every person is a point of awareness. Together, we see the world.

An Alaska-first Expo mobile MVP. Original text-led identity, teal/ice/amber controls, map filters, observation cards, foreground location, local place search, approximate-location report submission, account screens and Supabase foundation.

## Run
Requires Node 24 and npm. `npm ci`, then `npx expo start --dev-client`. MapLibre is native and **does not run in Expo Go**. Configure your own bundle IDs in app.json and authenticate with EAS, then `npx eas-cli build --profile development --platform android` (or ios). Install the resulting build on a device. iOS provisioning requires an Apple developer account; local iOS builds require macOS/Xcode. Android local builds require Java/Android SDK. EAS account, signing and build quota/costs are external prerequisites. No device build was executed in the cloud setup.

Without environment values the app uses explicitly labeled fictional DEMO observations. Reports persist only on the current device; no account is simulated. Optional Supabase setup: copy .env.example to .env.local, set your project URL and public anon key, apply supabase/migrations/202611050001_initial.sql through Supabase CLI or SQL editor, enable email/password auth and confirmation, configure email redirects and production CAPTCHA. Restart Metro after environment changes. Never use a service-role key in EXPO_PUBLIC variables. Accounts support registration, email confirmation, password sign-in, sign-out and display-name updates. Live reports are always unverified initially.

## Maps and licensing
MapLibre React Native 11 uses a native Expo config plugin; see https://maplibre.org/maplibre-react-native/docs/setup/expo and package version requirements. MIT React Native wrapper with MapLibre Native BSD-2-Clause components; no MapLibre API key. The app now has one topographic basemap; the empty Standard option is removed. Both the home map and report picker use the same local raster style, with no dependency on a blank vector demo basemap or remote font service. OpenTopoMap attribution (OpenStreetMap/SRTM, CC-BY-SA) remains visible. Review https://opentopomap.org/about before deployment; no SLA, bounded zoom and usage limits apply. Replace the development tile service with a licensed production provider before public launch. Styles stay dark around the map; topographic tiles use the provider's colors. No terrain elevation/extrusion is claimed.

Layers & sources separates the basemap, community reports and official-source layers. NWS and USGS parsers, source toggles, expiry handling and geometry overlays are prepared but **not connected** until endpoint and terms validation is complete. Weather, wildfire, road and 311 availability is explicit in the source screen. No live official reports are invented. See docs/official-sources.md for the exact network blocker and enablement checklist.

## Verification and limits
`npm run typecheck`, `npm run lint`, `npm test`; `npx expo export --platform android` checks JavaScript bundling, not native compilation. SQL migration needs a real disposable Supabase database to test RLS across anonymous, owner, other-user and moderator roles. The migration and 18 role-based security checks passed in a disposable PostgreSQL 17 / PostGIS database with an emulated Supabase auth.uid() harness. A hosted Supabase Auth/Storage integration still needs project credentials. Moderation is available through the protected `moderate_report(report, decision, explanation)` RPC, with decisions approve/hide/review; the Account → Moderator review screen calls the protected queue and decision RPCs. Add a trusted user to moderators through server administration. Reviewed means human review, never emergency-service confirmation.

Photos and typed report details now work in demo mode; shared uploads require the deployed private handler and migrations. Live official feeds, push delivery, full offline map tiles and a worldwide guaranteed POI directory are not implemented. Device smoke checks: pan/zoom, attribution, category filtering, card taps, cluster zoom, permission denial/allow, search, restart persistence, invalid submission, auth confirmation, and backend access-control checks. Do not treat this MVP as emergency guidance. Call 911 in an emergency.

## Reporting locations
Reports never ask users to type coordinates. Search the small offline Alaska gazetteer (including Beluga Point), choose current location with foreground permission, or tap Choose on map. The native picker opens a pan/zoom map: tap to place the amber pin, then confirm Use this location. Cancel preserves the previous selection. There is no default location; submission stays disabled until one is selected. Coordinates remain internal and are rounded before storage. Browser reporting supports place search and current location; pin placement is native-only. Saved places work offline; explicit online searches can find additional places and businesses. Coverage is not a guaranteed worldwide directory.

Device check after pulling this update: open Share an observation, search Beluga Point, select it, confirm the selected name, and submit a demo report. Also test current-location denial and Choose on map → tap → Use this location, plus Cancel preserving the prior location. This change uses existing native modules and does not require a new native build.

## Guided reporting
The three category buttons fit in one row. Each category offers editable starting titles (for example Outdoors → Whale sighting, Safety → Smoke observed, Travel → Icy road). The app does not use AI to infer incidents or generate factual descriptions. Changing categories preserves what you typed; choosing a suggested title explicitly replaces the title, which stays editable. Submit always requires a description and selected location.

## Latest update: richer reports, search and map controls
Wildlife reports support animal and approximate count; road reports support surface/visibility. Reports carry an observed time (Now, Earlier today or chosen date/time) separate from submission time. Selected place names, report kind, event time and details persist. Map/card colors share one definition: red hazards, orange smoke/fire, cyan flooding, green wildlife, teal trails, purple aurora, blue roads/travel. Gray circles are mixed clusters; white/purple markers are official sources. Color never implies verification. Cards show place, event age and source, and focus the native map when tapped. +/- zoom is available on the home map and pin picker. Nearby activity follows the native viewport; hosted queries use a bounded spatial RPC with a 300-report limit.

Town/feature search now includes Girdwood, Wasilla, Knik River and Knik Glacier offline. Search online adds OSM-based places and businesses via Photon; see docs/search.md for privacy, attribution, development usage limits and the unverified live-endpoint status.

Photo-library and native time-picker modules are new. On the Mac, preserve local configuration changes before pulling, then run `npm ci`, `npx expo prebuild --platform ios`, and `npx expo run:ios` from the Developer checkout (outside iCloud Documents). The prebuild step applies photo permissions/plugins; the native rebuild is required. Do not use --clean or discard local files to resolve a Git conflict. Open Xcode's Simulator manually if macOS automation blocks Expo window activation; then run `npx expo start --dev-client --localhost --port 8081` and connect the installed app to http://127.0.0.1:8081.

Shared accounts/reports still require a real Supabase project. Both migrations and the observation-photo Edge Function are needed for the latest build. No hosted backend was configured or deployed during this update. Follow docs/shared-backend.md; never put a service-role key in the app. Official weather/quake/fire integrations remain gated pending network/endpoint/terms validation; do not mistake them for live feeds.
