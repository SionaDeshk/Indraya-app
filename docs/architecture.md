# Architecture and boundaries
Expo Router screens → typed data adapter → Supabase or local demo storage. TanStack Query caches observations for one minute and exposes retry/error/empty states. Native MapLibre renders GeoJSON clusters. Foreground location is requested only after tapping Locate me or Use my current location. Browsing location is not stored. Reports require an explicit location selection through place search, a confirmed map pin, or current location; the selected report location is rounded by both the adapter and the database trigger. Raw device location is never submitted automatically. Public column grants exclude author_id; profiles are self-only.

Authentication uses the Supabase public anon/publishable key, persisted in AsyncStorage. Production should evaluate encrypted session storage and lifecycle refresh. RLS and column grants protect records; a security-definer RPC checks a server-managed moderator allowlist and records an audit action. Provision moderators only through trusted SQL administration. No mobile service-role key. Reports are limited to five per user per hour with a transaction lock; flags are unique per user/report. Email confirmation and Supabase Auth CAPTCHA/rate limits must be configured before public launch. Flags are limited to 20 per user per hour. Device-level anti-spam remains future work.

Official ingestion is gated pending validation; see docs/official-sources.md. Prepared NWS/USGS client adapters and separate source caches are never fetched while their validation timestamps are null. Future server-only adapters must return source URL, observed/expiry timestamps, external ID, validated terms and normalized geometry. NOAA/NWS, USGS, Alaska 511, avalanche and marine/tide sources each require separate endpoint, license, reliability and attribution review. No fictional official alerts are seeded. Notifications are a future opt-in, bounded server pipeline with deduplication, geographic scope, expiry and delivery audit; no push token collection, mass dispatch or background tracking exists.

Photo selection and metadata stripping work in demo mode. Shared photos use a private, owner-checked sanitizing Edge handler and a separate approval decision; a restrictive Storage policy prevents direct originals being uploaded even under broad pre-existing policies. See shared-backend.md for deployment and limitations. Search uses explicit, cached Photon requests for places and businesses, without a fixed-place fallback; see search.md for licensing, privacy and live-endpoint validation status. Hosted nearby activity uses a bounded PostGIS RPC, capped at 300 reports per map area, and never returns author IDs or hidden reports. Native map/zoom, photo permissions and native date/time controls still need device validation.

The original brand mark depicts six connected awareness points and an amber central point. The reproducible Pillow script in scripts/create-brand.py generates the icon assets; Pillow is only needed when changing the mark, not to install or run the app.

Home and location picker now share one local topographic raster style. Layer availability lives in the source catalog; session layer selection uses the shared query cache. Source data stays separate from user-authored observations and cannot be flagged or edited as community content. The third migration adds a versioned observation catalog, privacy holds and audited staff assessments; see guided-observations.md.

Report type, public place label, observed time and structured wildlife/road details are stored separately from title/description and submission time. Type colors come from one shared definition used by GeoJSON markers, cards and legend. Legacy device reports fall back to category colors and submission timestamps. Photo upload is a second step after report creation: retries reuse its ID, preserving successful reports without duplicates. Auth changes reset private photo caches, and native auth refresh follows foreground/background lifecycle without location tracking.
